# DHT11 单总线温湿度驱动（非阻塞调度版）

> 一段可复用、可移植的 DHT11 驱动：主循环反复调用一个函数，驱动内部自己调度
> 「2 秒间隔 → 20ms 起始信号 → 4ms 阻塞读取」三步，读成功才返回一次 `DHT11_OK`。
> 本工程把它挂在 PA11，作为 Modbus 地址 `0x02` 虚拟从机的数据源。

---

## 1. 一句话定位

DHT11 是**单总线**传感器：一根数据线既要发命令（起始信号），又要读应答和 40 位数据。
这个驱动把「毫秒级节奏」和「微秒级时序」拆成两层处理：

- **毫秒级**（起始信号 20ms、两次读取间隔 2s）→ 状态机 + `HAL_GetTick()`，**非阻塞**
- **微秒级**（应答脉冲 + 40 位数据，每 bit 只有 26~70µs）→ 集中在一次约 4ms 的**阻塞**读取里

结论：主循环其余时间不会被长时间卡住，这是单总线传感器的合理折中。

## 2. 硬件接线

| 项 | 值 |
|---|---|
| 数据脚 | **PA11**（本工程 PA1=RS485 DE、PA2/3=USART2、PA9/10=USART1、PA13/14=SWD、PC13=LED，PA11 空闲） |
| 供电 | 3.3V / 5V（本工程 3.3V） |
| 上拉 | 代码已开 GPIO 内部上拉；**建议再加 4.7k~10k 外部上拉**，单总线靠上拉复位电平，外部上拉更抗干扰 |

> 引脚可换：改 `dht11.h` 顶部「① 可移植配置区」的 `DHT11_GPIO_PORT` / `DHT11_GPIO_PIN` 即可，
> 端口时钟由 `DHT11_ClockEnable()` 运行时自动判断，不用改 CubeMX。

## 3. 对外接口

| 函数 | 作用 |
|---|---|
| `void DHT11_Init(DHT11_Handle_t *dht)` | 复位状态机 + 使能 DWT 微秒计时。**必须在 `SystemClock_Config()` 之后调用**，否则 `SystemCoreClock` 不是 72MHz，微秒换算整体偏大 |
| `DHT11_Status DHT11_Handler(DHT11_Handle_t *dht)` | 主循环反复调用，内部自动调度。返回 `DHT11_OK` = 本次刚完成一次成功读取 |
| `float DHT11_GetTemp(...)` / `DHT11_GetHumi(...)` | 取结果（℃ / %RH），内部做了整数+小数合并 |

```c
DHT11_Handle_t dht;
DHT11_Init(&dht);
while (1) {
    DHT11_Status st = DHT11_Handler(&dht);   // 反复调用，内部自动调度
    if (st == DHT11_OK) {
        float t = DHT11_GetTemp(&dht);       // 每 2 秒拿到一次新数据
        float h = DHT11_GetHumi(&dht);
    }
}
```

返回状态枚举：

| 状态 | 含义 |
|---|---|
| `DHT11_BUSY` (0) | 正在调度中（等 2s 间隔 / 起始信号进行中），暂无新数据 |
| `DHT11_OK` (1) | 本次完成一次成功读取，新数据已就绪 |
| `DHT11_ERROR` (2) | 读取失败：无响应（超时）或校验和不匹配 |

## 4. 代码分层（由底向上读）

| 层 | 函数 | 说明 |
|---|---|---|
| A 引脚抽象 | `DHT11_SetOutput/SetInput/WriteLow/Read` | 对 HAL 的薄封装，换芯片只改这一处 |
| B 微秒计时 | `DHT11_GetUs` / `DHT11_WaitLevel` / `DHT11_MeasureHighUs` | 基于 **DWT 周期计数器**，摆脱 `HAL_Delay` 的 ms 精度；用 `uint32` 减法判间隔，翻转自动处理 |
| C 位级读取 | `DHT11_ReadFrame`（外层关中断）/ `DHT11_ReadFrame_Inner` | 应答 + 40 位数据的紧贴时序读取，阻塞约 4ms |
| D 毫秒调度 | `DHT11_Handler` / `DHT11_Init` | 状态机 + `HAL_GetTick()`，非阻塞驱动整体节奏 |

## 5. 两个必须理解的坑

### 5.1 应答脉冲被当第 0 位（整帧右移一位）

DHT11 应答是「拉低 80µs → 拉高 80µs」。真正的数据要从**这个 80µs 高电平结束之后**才开始。
如果读完「拉高」就立刻进 40 位循环，第一个 `WaitLevel(SET)` 会立刻返回、什么都不等，
`MeasureHighUs` 就把这 80µs 应答脉冲当成第 0 位（实测 86µs > 40µs 判成 `1`），
**整帧右移一位、第 40 位永远读不到、校验和对不上**。

表现是「约半数读成功但数值离谱」（如 H=155.128%RH、T=14.3℃）。修正就是补第三次 `WaitLevel`，
等这段应答高电平**结束**（下降沿）再开始读数据。

### 5.2 读取期间必须关中断

单总线每 bit 的可判窗口只有 26~70µs，本工程 USART1 在 115200 下每 87µs 就来一次接收中断，
一次 ISR 就足以把 `0` 的高电平测成 `1`，或错过边沿导致整帧错位。
所以 `DHT11_ReadFrame()` 用 `__get_PRIMASK()` 保存、`__set_PRIMASK()` 恢复的方式关中断约 4ms。

- **为什么用 PRIMASK 保存/恢复而不是直接 `__enable_irq()`**：若外层还有临界区，直接使能会提前打开中断、破坏外层保护
- **为什么 DWT 计时不受关中断影响**：DWT 是硬件周期计数器，与中断开关无关

### 5.3 关中断 4ms 的副作用

关中断期间若 PC 正在向 USART1 发帧，后续字节会因接收寄存器溢出（ORE）丢失、该帧作废。
本工程在主循环里只做「两条总线都静默才驱动传感器」的保护（见 `main.c`），
把这段 4ms 挪到总线空闲的缝隙里。链路本身不会卡死（`HAL_UART_ErrorCallback` 双路恢复），
Modbus 主站也有超时重发兜底。

## 6. 校验与数据格式

传感器返回 5 字节：

| 字节 | 内容 |
|---|---|
| 0 | 湿度整数（%RH） |
| 1 | 湿度小数 |
| 2 | 温度整数（有符号） |
| 3 | 温度小数 |
| 4 | 校验和 = 前 4 字节相加取低 8 位 |

校验不匹配 → 返回 `DHT11_ERROR`。

## 7. 调试观测（`DHT11_DEBUG_TIMES`）

`dht11.h` 里把 `DHT11_DEBUG_TIMES` 置 1 后，会额外记录：

- `DHT11_DbgBitUs[40]`：40 位各自的高电平宽度（µs）
- `DHT11_DbgRaw[5]`：最近一次原始 5 字节
- `DHT11_DbgFailStage` / `DHT11_DbgFailBit`：失败发生在哪个阶段、哪一位

诊断套路（对应「读回 0.0 但 ok 计数在涨」这类问题）：

| 现象 | 判断 |
|---|---|
| 位宽全 0 | DWT 计时没在跑（`DHT11_Init` 调用位置不对，或在 `SystemClock_Config` 之前） |
| 位宽 26/70µs 交替 | 时序正常，问题在传感器本身或校验逻辑 |
| 开头出现 80µs 量级 | 应答脉冲没被跳过，整帧错位（见 5.1） |
| 全 0xFF / 全 0 | 线被钳住或没接上拉 |

验证通过后改回 0，不影响任何功能代码。

## 8. 移植清单

换芯片/换引脚只需改 `dht11.h` 顶部几个宏：

| 宏 | 默认 | 说明 |
|---|---|---|
| `DHT11_GPIO_PORT` / `DHT11_GPIO_PIN` | `GPIOA` / `GPIO_PIN_11` | 数据脚 |
| `DHT11_START_LOW_MS` | 20 | 起始信号低电平（要求 ≥18ms，留余量） |
| `DHT11_READ_INTERVAL_MS` | 2000 | 两次读取最小间隔（手册要求 ≥1000ms） |
| `DHT11_BIT_1_US` | 40 | 判 bit 为 1 的高电平阈值（`0`≈26~28µs，`1`≈70µs） |
| `DHT11_LEVEL_TIMEOUT_US` | 200 | 等待电平的最长超时 |
| `DHT11_DEBUG_TIMES` | 0 | 调试观测开关 |

`DHT11_ClockEnable()` 里已覆盖 GPIOA~E 五个端口；用到 F 系列更多端口时按同样写法补一行。
